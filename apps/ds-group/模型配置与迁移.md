# 模型、参与方式与升级

适用于 DSCord 0.4.0-alpha.7。业务模型、决策模型和可选记忆嵌入分别配置。

## 业务模型

Bot 使用 DSH 模型目录中的完整 `provider/model-id` 引用，服务商、端点、凭据与思考设置由 DSH 提供。`provider/model-id` 只是可替换的格式示例；项目没有要求某个业务模型。模型必须支持实际工作需要的工具、上下文和输入类型。

模型在网页上选：“添加 Bot”和“我的 Bot → 设置”里的模型选项，是运行这个 Bot 的设备报告给中央的模型目录；留空表示跟随设备默认。选择保存在中央，设备下一次报告时取回，并调用内核的 `update-bot`，仍是同一 Bot 和 Session。设备上没有这个模型或它缺密钥时，Bot 继续用原来的模型运行，网页显示原因。已有生成请求的模型处理由宿主管理，不通过重新建 Bot 来迁移历史。原生模型配置不复制到另一套独立 DSH home。

业务模型不可用时，先在 DSH 检查目录与凭据。不要把决策模型、嵌入模型或管理员示例账号填入业务模型栏。

## 决策模型

决策模型判断 Bot 什么时候该开口，和 Bot 回答用的业务模型是两回事。它是完整使用 DSCord 的必需项，每台运行 Bot 的设备各配一次，这台设备上的 Bot 共用。它做两件事：

- 参与判断：`natural`（自然参与）的 Bot 没被点名时，靠它选择 LISTEN、WAIT 或 SPEAK；`shadow` 观察并形成判断但不主动发言。
- 接话时机：同一个人连发几条消息时，靠它判断是等对方说完（WAIT）、把新消息并进正在写的回答（JOIN），还是分开回答（REPLY）。所有参与方式都用到。

没有可用的决策模型时，Bot 只在被点名或收到私聊时回应，自然参与不起作用；连发的消息按固定时间等一下再答，后到的消息一律并进正在写的回答。判断只决定是否开启原有对话回合，不授权工具、外部账号或任务变更。

在 DSH 的 DSCord 页面里，选择“决策模型 → 服务预设”，再填写该服务的凭据。模型和完整服务地址会自动填入，可按自己的服务配置调整。每台设备配置一次，设备上的 Bot 共用该服务。

| 服务预设 | 默认模型 | 认证与地址 |
|---|---|---|
| OpenAI Decisions | `gpt-6-luna` | OpenAI API key，默认 `https://api.openai.com/v1/decisions` |
| TypeSafe Jev | `jev-1.14.0` | TypeSafe API key，默认 `https://api.typesafe.ai/v1/systemone`；也可选择已列出的版本或填写兼容模型名 |
| Cloudflare Clef | `clef`，可选 `clef-flash` | Workers AI API token 与 Cloudflare Account ID；自动构造当前模型的 Workers AI REST 地址 |

Clef 与 Jev 使用相同的 System One 请求：`state` 加以 ID 为键的 `questions`，choice 选项放在 `criteria` 中；返回 `answers` 映射与类别概率。Cloudflare REST 在外面加 `success/result/errors/messages` 包装，因此共享 System One 判断逻辑，另处理 Cloudflare 包装和账户地址。OpenAI Decisions 使用独立协议，不能填写普通 Chat Completions 地址。[Jev Choice](https://docs.typesafe.ai/primitives/choice) · [Clef 模型与接口](https://developers.cloudflare.com/workers-ai/models/clef/) · [Cloudflare REST](https://developers.cloudflare.com/workers-ai/get-started/rest-api/)。本轮接入处理文本/JSON 判断，没有接入这些服务的媒体输入或其他问题类型。

Cloudflare 账户 ID 可从 Workers AI 页面复制，应为 32 位十六进制字符；不要填写 Zone ID。令牌须有该账户的 Workers AI 权限。自动生成的地址形式为 `https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/run/@cf/cloudflare/clef`，选 Flash 时路径和请求模型一同变化。需要代理时可以填写完整的 Workers AI REST 兼容地址；HTTP 内网地址和 HTTPS 都可用，URL 不能带用户名、密码或 fragment。

“保存并验证”会顺序发送两个不含个人聊天的合成小问题，分别检查参与判断和接话接口。第一项失败后停止，不自动重试。启动时也会检查；这些请求可能计费。界面据此显示“运行正常”或“请求失败”，不把协议连通当成中文语义准确率证明。配好后表单收起，点击“修改设置”可继续调整。

之后群里每一次真实判断也会更新这个状态。保存时的“已保存，决策模型可以用了”只在状态仍然正常时显示；之后某次判断失败，面板改为“请求失败”，并在错误码下面显示服务自己返回的原因（例如 `max_tokens_exceeded`），其中的 API key 和 Bearer 令牌会替换成 `***`。这段原因只显示在本机面板，不报告给中央。

发给决策模型的是精简后的判断材料（`src/decision-state.mjs`）：人和消息用 `P1`、`M1` 这样的短编号，不带 Matrix ID、名字来源和投递回执；单条消息超过 1200 字截断；整份材料限制在 20000 字符以内，超出时先丢最早的群聊记录，正在判断的消息总会保留。TypeSafe Jev 默认每个问题最多读 32k token，超出会返回 `400 max_tokens_exceeded`；这个预算让常见的长群聊也留在限制内，不需要开启 Jev 的长上下文请求头。节点自己的判断记录（`attention_decisions.input_json`）仍保存完整材料，便于排查。

每个服务分别保存凭据；切换预设会清空当前输入框，不会把上一家的 key 发给新服务。切回已配置的服务时可以留空沿用它自己的凭据。凭据不回显，填写新值才替换；不修改 Bot 身份、Session 或记忆。

设备每次向中央报告时带上决策模型的状态（是否有凭据、是否启用、是否可用、模型名和最近的错误码），不带凭据和服务地址。网页“我的 Bot”的设备列表、“添加 Bot”的运行设备下面和 Bot 上线后的提示会据此提醒这台设备还没有配好决策模型；配置本身只在 DSH 里做。

连接数据目录中的 `decision-provider.json` 以 `0600` 模式保存。v2 配置包含 `version/enabled/preset/profiles`，每个服务的 `apiKey/model/endpoint/accountId` 位于自己的 profile。旧 v1 配置读取时按 OpenAI Decisions 迁移，保留已有私有地址、模型和凭据；读取不重写旧文件，下一次保存才写 v2。

私有设置优先于环境。`DSCORD_DECISION_PRESET` 可选 `openai-decisions`（默认）、`typesafe-jev`、`cloudflare-clef`。`DSCORD_DECISION_API_KEY/MODEL/ENDPOINT` 只属于环境中选定的服务；在 UI 切换到另一服务不会复用这些变量。各家认证还可分别通过 `OPENAI_API_KEY`、`TYPESAFE_API_KEY`、`CLOUDFLARE_API_TOKEN`（兼容 `CLOUDFLARE_AUTH_TOKEN`）提供。Cloudflare 账户支持 `CLOUDFLARE_ACCOUNT_ID` 或选定该预设时的 `DSCORD_DECISION_ACCOUNT_ID`。

例如，在启动节点的环境选择 Jev：

```sh
export DSCORD_DECISION_PRESET='typesafe-jev'
export DSCORD_DECISION_MODEL='jev-1.14.0'
# TYPESAFE_API_KEY 由自己的私有环境提供
```

Cloudflare 则选择 `cloudflare-clef`，设置自己的 `CLOUDFLARE_ACCOUNT_ID` 与 `CLOUDFLARE_API_TOKEN`；需要 Flash 时设置 `DSCORD_DECISION_MODEL='clef-flash'`。这些型号是预设默认值，业务模型仍由 DSH 目录独立配置。

一个没有任何凭据的 v2 配置示例：

```json
{
  "version": 2,
  "enabled": true,
  "preset": "typesafe-jev",
  "profiles": {
    "typesafe-jev": { "model": "jev-1.14.0" }
  }
}
```

管理 action `save-decision-provider` 接受 `preset?/apiKey?/enabled?/model?/endpoint?/accountId?`，省略 preset 时修改当前服务。模型和地址清空后恢复为该服务的环境值或默认值。保存后重建 provider，并通过现有配置代次使旧参与判断失效。直接修改文件后须重启节点；对外只报告配置、可用状态与模型标识，不回显账户 ID、地址或凭据。[私有配置](dsh-connect/decision-settings.mjs) · [预设](src/decision-presets.mjs) · [协议适配](src/decision-provider.mjs)

网页只显示已配置、可用或未知状态。服务尚未成功调用时，可用状态可能未知；服务故障与正常 LISTEN/WAIT 不同。服务器持久保存参与方式，节点同步后显示已应用。自然参与仍可能漏接、误判或等待过久，重要请求应直接点名。

## 独立 CLI 的模型配置

这一路径使用自己的 DSH home，从选定来源 profile 读取并复制所需配置；它与图形节点直接复用现有宿主不同。先在该 profile 配好模型，再运行节点：

```sh
export DS_GROUP_DSH_SOURCE_HOME='/absolute/path/to/your/dsh-home'
export DS_GROUP_DSH_SOURCE_PROFILE='your-profile'
export DS_GROUP_MODEL='provider/model-id'
```

示例路径、profile 和引用都须替换。第一个 `/` 分隔 provider，模型 ID 本身可含 `/`。选择顺序是显式 `DS_GROUP_MODEL`、节点已保存选择、来源 profile 默认值。仅当这些均不存在时，保留旧版环境凭据的兼容回退；新部署应配置自己的来源模型。

`DS_GROUP_MAX_OUTPUT_TOKENS` 控制兼容 CLI 的单次输出上限，默认 4096；`DS_GROUP_REASONING_EFFORT` 只应填写所选模型支持的值。配置读取基于固定 DSH 0.2.2-rc.1 的 profile/bundle 与 `llm-pi-ai` 目录结构；额外 adapter 或动态 JavaScript 配置并未声明通用兼容。

导出内容限于所选 provider 所需的目录、覆盖项、协议、端点、headers、重试和认证引用。私有 `model-source.json` 与独立 home 的凭据文件按 `0600` 保存；来源 profile 只读。服务用户必须能读取来源配置，使用环境认证时也须有对应环境变量。

## 额度和费用边界

Core 的 `allowedModels`、`modelCallLimit` 和 `maxOutputTokens` 预算账本用于兼容 CLI 适配器。`allowedModels` 省略或为 `null` 时开放，空数组暂停该路径的新模型请求。次数和输出额度在新数据库首次初始化时写入，修改 JSON 不会重置既有账目或额度。

原生图形连接的完整调用由 DSH 管理，连接层观察的用量不是整个 Session 的完整账单；不能把 Core 的 CLI 预算当成所有原生调用的硬上限。参与判断、记忆整理和嵌入也可能分别产生调用。费用及额度控制应结合 DSH 设置、节点配置与服务商账户限制。

provider 内部重试、缓存和失败请求的收费口径由对应服务商决定。界面显示已完成任务不证明费用数据完整。

## 升级

备份后将 Core、客户端和节点升级到同一发行版本，保留原数据目录和 Matrix 身份域。已有 `ds-bot` 团队先停止旧插件，再重载 DSCord。[内核迁移](deploy/kernel-runtime.md)

独立节点沿用已保存的模型选择和 Session；切换前检查运行中任务，上线后核对实际模型。未知完成状态和历史账目继续保留，不能通过更换模型结清或抹去。
