# 模型、参与方式与升级

适用于 DSCord 0.4.0-alpha.2。业务模型、自然参与判断和可选记忆嵌入分别配置。

## 业务模型

Bot 使用 DSH 模型目录中的完整 `provider/model-id` 引用，服务商、端点、凭据与思考设置由 DSH 提供。`provider/model-id` 只是可替换的格式示例；项目没有要求某个业务模型。模型必须支持实际工作需要的工具、上下文和输入类型。

图形节点在 DSCord 中创建 Bot 时选择模型；已经加入服务器的 Bot 可在连接页的模型控件保存新选择。保存调用内核的 `update-bot`，仍是同一 Bot 和 Session。已有生成请求的模型处理由宿主管理，不通过重新建 Bot 来迁移历史。原生模型配置不复制到另一套独立 DSH home。

业务模型不可用时，先在 DSH 检查目录与凭据。不要把参与判断服务的模型、嵌入模型或管理员示例账号填入业务模型栏。

## 参与判断服务

默认 `mention` 模式在被点名或收到私聊时回应，不需要单独的参与判断服务。`shadow` 观察并形成判断但不主动发言；`natural` 允许选择 LISTEN、WAIT 或 SPEAK。参与判断只选择是否开启原有对话回合，不授权工具、外部账号或任务变更。

随包适配器使用 Decisions 协议，默认地址为 `https://api.openai.com/v1/decisions`，默认模型为 `gpt-6-luna`。这是 adapter 默认值，不是平台 provider/model 白名单。可用 `DSCORD_DECISION_ENDPOINT` 和 `DSCORD_DECISION_MODEL` 设置支持该协议的服务与模型，或在私有配置中保存 `endpoint/model`。地址必须是完整 Decisions endpoint，不能填写 chat completions 接口；HTTP 内网代理和 HTTPS 都可用，URL 不能带用户名、密码或 fragment。其他协议未声明兼容。

在 DSH 的 DSCord 页面展开“参与判断服务”，填写自己的凭据并选择是否启用。凭据保存后不回显，留空保留已有值。连接数据目录中的 `decision-provider.json` 模式为 `0600`，其配置结构为 `version/enabled/apiKey/model?/endpoint?`。模型与地址的优先级是私有保存值、对应 `DSCORD_DECISION_*` 环境变量、adapter 默认值；凭据优先级是私有保存值、`DSCORD_DECISION_API_KEY`、兼容回退的 `OPENAI_API_KEY`。不要把这些私有值放入网页静态配置。

使用环境配置时，在启动 DSH 节点的环境设置上述变量；直接修改私有配置文件后重启节点读取。管理 action 保存后会重建判断 provider。一个不包含凭据的私有配置示例为：

```json
{
  "version": 1,
  "enabled": true,
  "model": "your-decisions-model",
  "endpoint": "https://decisions.example.com/v1/decisions"
}
```

模型与地址是可替换占位示例，必须由同协议服务实际支持；凭据由私有文件或节点环境提供。

本机 `save-decision-provider` 管理 action 接受 `apiKey?/enabled?/model?/endpoint?`；图形表单可管理凭据和启用状态，设置其他字段可使用私有配置或该 action。对外状态只返回实际模型与配置、可用状态，不回显 endpoint 或凭据。[配置实现](dsh-connect/decision-settings.mjs) · [Decisions adapter](src/decision-provider.mjs)

网页只显示已配置、可用或未知状态。服务尚未成功调用时，可用状态可能未知；服务故障与正常 LISTEN/WAIT 不同。服务器持久保存参与方式，节点同步后显示已应用。自然参与仍可能漏接、误判或等待过久，重要请求应直接点名。

## 独立 CLI 的模型配置

这一路径使用自己的 DSH home，从选定来源 profile 读取并复制所需配置；它与图形节点直接复用现有宿主不同。先在该 profile 配好模型，再运行节点：

```sh
export DS_GROUP_DSH_SOURCE_HOME='/absolute/path/to/your/dsh-home'
export DS_GROUP_DSH_SOURCE_PROFILE='your-profile'
export DS_GROUP_MODEL='provider/model-id'
```

示例路径、profile 和引用都须替换。第一个 `/` 分隔 provider，模型 ID 本身可含 `/`。选择顺序是显式 `DS_GROUP_MODEL`、节点已保存选择、来源 profile 默认值。仅当这些均不存在时，保留旧版环境凭据的兼容回退；新部署应配置自己的来源模型。

`DS_GROUP_MAX_OUTPUT_TOKENS` 控制兼容 CLI 的单次输出上限，默认 4096；`DS_GROUP_REASONING_EFFORT` 只应填写所选模型支持的值。配置读取基于固定 DSH 0.2.2-rc.1 的 profile/bundle 与 `llm-pi-ai` 目录结构；额外 adapter 或动态 JavaScript 配置并未声明通用兼容。

导出内容限于所选 provider 所需的目录、覆盖项、协议、端点、headers、重试和认证引用。私有 `model-source.json` 与独立 home 的凭据文件按 `0600` 保存；来源 profile 只读。服务用户必须能读取来源配置，使用环境认证时也须有对应环境变量。

## 额度和费用边界

Core 的 `allowedModels`、`modelCallLimit` 和 `maxOutputTokens` 预算账本用于兼容 CLI 适配器。`allowedModels` 省略或为 `null` 时开放，空数组暂停该路径的新模型请求。次数和输出额度在新数据库首次初始化时写入，修改 JSON 不会重置既有账目或额度。

原生图形连接的完整调用由 DSH 管理，连接层观察的用量不是整个 Session 的完整账单；不能把 Core 的 CLI 预算当成所有原生调用的硬上限。参与判断、记忆整理和嵌入也可能分别产生调用。费用及额度控制应结合 DSH 设置、节点配置与服务商账户限制。

provider 内部重试、缓存和失败请求的收费口径由对应服务商决定。界面显示已完成任务不证明费用数据完整。

## 升级

备份后将 Core、客户端和节点升级到同一发行版本，保留原数据目录和 Matrix 身份域。已有 `ds-bot` 团队先停止旧插件，再重载 DSCord。[内核迁移](deploy/kernel-runtime.md)

独立节点沿用已保存的模型选择和 Session；切换前检查运行中任务，上线后核对实际模型。未知完成状态和历史账目继续保留，不能通过更换模型结清或抹去。
