# 当前上下文、来源与按需回顾

本指南说明 DSCord 0.4.0-alpha.4 的记忆读取和接口语义。它描述程序能提供的证据与边界，不保证模型每次都正确选择、理解或使用了这些证据。配置和数据位置见[运行指南](复用与运行.md)。

## 每个 Bot 的知识范围

来源正文、修订与记忆位于同一 `knowledge.sqlite`。观察记录只增加每 Bot 的来源引用与本地序号，不复制消息正文或建立第二份可编辑事实库。人物和项目视图是读取结果，不是全体成员共同的档案。

人物以全局身份 ID（`用户名@中央域名`）为键：聊天服务器 roster 给出账号的 `globalId` 时，来源的 `authorId`、联系人和记忆主体都记这个身份，`authorAccount` 记下来源所用的账号（由此知道来自哪台服务器），同一个人在几台服务器上的账号由 `identity_accounts` 归到同一身份；用账号 ID 查人物、主体或说话人时先换成它背后的身份。给不出全局身份的账号以 `matrix:<账号>` 作身份。同名人物按身份区分。联系人名称、别名和房间标签限于该 Bot 实际见过的来源、合法记忆引用与所见成员，不因全局目录里有一个 ID 就带入另一个 Bot 的私聊别名。旧数据无法证明名称来源时显示稳定 ID；未知作者、时间和受众不猜填。

记忆范围说明来源的适用位置，不证明房间里的所有人都知道、同意或有相同心理状态。当前工作、任务完成和文件交付仍须来自任务运行时及真实回执。

## 持续观察和水位

`MemoryService.observe(botId, inputs, options)` 事务接纳已观察事件；不切换当前请求，也不直接调用模型或向量服务。来源包含稳定事件、房间、作者、种类、正文和时间。启用 `streamId` 时提供 `cursor`，可用 `afterCursor` 比较并提交；重复同 cursor 和同事件不重写正文，批次冲突不部分提交。

| 水位 | 表示什么 |
|---|---|
| `receivedThrough` | 已持久接纳的本 Bot 观察序号 |
| `reviewedThrough` | 从首条开始连续完成整理确认的位置 |
| `settledThrough` | 连续已整理或因修订／撤回失效的位置 |
| `pendingReviewCount` | 当前版本仍等待整理的来源数量 |
| `contextThrough` | 已确认组装有预算视图的位置 |

这些水位不等于完整 Matrix 历史、全部消息入模、语义理解或外部操作完成。整理结果经过来源版本与目标修订检查，在单个发布事务提交；来源期间变化则不作为当前事实发布。

## 当前请求与其他工作

持续旁听到的新请求不等于当前回合已经接纳它。可靠路由把来源区分为上下文、排队请求及精确关联的任务更新；未领取的另一个请求不会作为当前的新指令注入。当前请求在实际 SDK 领取消息后准备首步来源，随后正式追加保持幂等。

没有稳定原事件或 SDK 消息标识时，来源视图应明确 unavailable，不能沿用上一房间、作者和正文。跨 Session part 或压缩后，保留的原文引用仍指向实际输入，不把包装信息当成新的人类陈述。

已接纳旧请求可以作为显式检索的工作证据，仍不是当前的新指令。“已接纳”只证明进入过对应工作，不能代替执行或送达回执。

## 有预算的只读视图

`attentionView(botId, options)` 与 `contextSnapshot(botId, sessionId)` 组装当前人物、项目和来源视图。常用 options 为 `roomId/threadRootId/eventIds/query/subjectIds/projectIds/budgetChars`；完整实现见 [views.mjs](views.mjs)。

v2 包含 `self/speaker/people/currentClaims/preferences/projectFacts/changes/recentSources/historyGaps/watermarks/version/knowledgeBoundary/budget`。每条陈述保留身份、属性、范围、来源、修订、依赖和冲突：

- `kind` 区分直接陈述、转述、工具观察、推断及 legacy。
- `claimState` 区分 statement、proposal、confirmed、uncertain；字段值本身不是外部确认的证明。
- `sources/sourceRefs` 指向原作者、房间、事件、时间与摘要校验，未知时间为 `null`。
- `basisRefs` 记录所依据的已有记忆及精确修订；依赖失效会要求复核。
- `changes` 展示已变化、过期、撤回或依赖失效的历史内容，不继续当作当前事实。

近期尚未整理的原文也可作为来源材料；并列冲突不因排序而被自动裁决。人类估计、实际工具结果和不同文件版本应分别解释，不能只按说话人种类决定真伪。

默认视图预算 12000 个 JSON 字符，可在实现支持的 4096–32000 范围内调整。`budget.omitted`、`truncated` 和 `historyGaps` 保留裁剪与覆盖缺口。某条事实没有出现在有限视图中，不等于它从未存在或已经失效。

## 人物、项目和原文接口

DSH 管理 API 使用 `memory-profiles` / `memory-profile`；Core 的 owner 接口为 `GET /api/bots/:botId/memory/profile`。无 `id` 时列实体，有 `id` 时读取对应视图，`kind` 为 `person` 或 `project`。记忆变化走 `GET /api/bots/:botId/memory/changes`（节点 `memory-history`，按 `before` 翻页），状态主页的“记忆”页显示。Core 检查所属人并通过节点通道读取；刷新视图不主动生成模型回答。

列表返回 `{kind,items,more}`。每项有稳定 `id/name/kind`、实体类别、来源范围和当前／历史计数。单个 profile 返回 `{kind,id,identity,view}`，未知实体报告 `MEMORY_PROFILE_NOT_KNOWN`。`roomId` 可缩小范围，不能据显示名合并实体。

`memory_source` 精确回读本 Bot 有权见到的来源修订。`raw_source_query` 按主题、实体和文件关联检索本 Bot 实际观察的原文片段，保留原作者、房间、时间、修订、受众和工作归属。`authorKind` 可限定 human、bot、tool 或 unknown；native 是 transport，不是作者种类。默认结果最多 6 条、总预算 10000 字符；显式上限及其他参数以工具 schema 为准。

相关来源不等于可以向任意房间披露私聊内容。未接纳请求及其派生仍受工作边界约束；只有本 Bot 的来源可见，不从另一 Bot 的来源表补足历史。

## 修订、撤回和回顾

编辑须在目标已知且作者一致时推进原来源修订；未核对关系保留缺口，不冒充目标作者。撤回保存通知与历史状态，晚到原文不复活被撤回的事实。

`review_memory` 按人物、项目或问题选择有预算的来源，使用现有提案校验与版本化发布进行按需回顾。它可能调用 Bot 的业务模型，不是每次闲聊必做的操作。来源和依据修订变化后，派生记录失效；没有登记依据的旧文件不因此自动修复。

后台整理在停机时取消新工作，等待持久操作收尾，未完成来源保持待整理。迟到结果不得在内核释放后发布；重启可以继续处理原队列。索引只是派生数据，重建索引不改来源事实。

## 实际限制

持久保存、上下文覆盖和模型正确使用是不同层次。模型仍可能漏查原话、错误沿用旧稿，或用另一个文件／测试版本的新结果否定旧记录。需要改结论时，应定位原来源、对应文件版本与真实相反证据；同伴缺少引用不等于原事实已被推翻。

有限视图、词匹配和语义排序都不能保证找全历史。记忆不提供读心、全员共识或外部完成证明，原始来源与工作回执保留其各自作用。
