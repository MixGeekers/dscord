# 来源记忆：配置与运行

DSCord 0.4.0-alpha.6 的来源记忆保存在 Bot home 下的 `knowledge/`。每个 Bot 的认识来自它实际观察的来源及明确共享记录，人物使用稳定账号 ID 区分，显示名不触发合并。来源、记忆修订和当前视图使用同一结构库；不另建可独立编辑、可能漂移的人物摘要库。

## 默认运行

不配置语义后端即可使用 SQLite 精确/文本检索，返回 `mode: exact`。普通人物/项目视图和原文读取不调用业务模型；自动整理和显式按需回顾可能调用 Bot 的已选模型，费用与业务模型由部署者管理。

DSCord 自有内核接入 `remember`、`recall`、`forget`、来源回读与记忆面板。旧 `ds-bot` 团队须先停止旧插件，再由 DSCord 在原 home 接管，不能同时运行两个内核，也不会隐式退回旧实例。[内核运行](../deploy/kernel-runtime.md)

原生 Markdown 记忆首次采用时可导入，原文件保留并标为 legacy 来源。缺少的作者、房间或时间保持未知，不补成已核验事实。原 Session 与 Bot ID 保留，断开聊天服务器不删除记忆。

## 可选 Ombre/Harrier 后端

语义后端使用随包 `service/ombre/` 的受控扩展。固定上游、Python 基线、源码与依赖摘要见 [SOURCE.json](../service/ombre/SOURCE.json) 和 [requirements.lock.txt](../service/ombre/requirements.lock.txt)。这是后端兼容约束，不是聊天业务模型的要求。

依赖锁按 Python 3.12 生成，SOURCE.json 记录的运行环境为 CPython 3.12.16；这是来源快照的环境记录。准备可运行锁定依赖的独立 Python 环境和匹配的 Ombre 源码，其他环境的兼容性须自行核对。自管嵌入模式还需要对应平台的 `llama-server` 与匹配 GGUF，模型摘要由 [memory/ombre.mjs](ombre.mjs) 的 `HARRIER` 固定并在启动时核对。当前 profile 的 query/document 格式、1024 维、归一化等约束见 [harrier_profile.py](../service/ombre/harrier_profile.py)，不能将任意 embedding 服务当成兼容替代。

从应用或发行包根目录执行。以下全部路径需要替换为自己准备的文件；该命令保存配置，下一次内核启动时生效：

```sh
node scripts/memory-setup.mjs --home /absolute/path/to/dsh-home \
  --python /absolute/path/to/python \
  --ombre /absolute/path/to/pinned-ombre-source \
  --llama-server /absolute/path/to/llama-server \
  --gguf /absolute/path/to/matching-model.gguf
```

已有兼容 Harrier 服务可用 `--endpoint` 代替 `--llama-server` 与 `--gguf`，例如 `--endpoint http://127.0.0.1:PORT/v1/embeddings`；地址与端口只是占位示例。外部服务的模型、profile 和维度仍须匹配，进程由部署者维护，DSCord 不负责终止它。

使用 `--home` 时配置写入该 DSH home 的 `bot/knowledge/backend.json`。指定独立的精确内核目录时，改用 `--kernel-home /absolute/path/to/kernel-home`，写入其 `knowledge/backend.json`，不再追加 `bot/`；两参数互斥。内核目录可从 `kernel-info` 的 `runtime.home` 核对。配置文件模式为 `0600`。也支持 `DSCORD_MEMORY_PYTHON`、`DSCORD_MEMORY_OMBRE` 及 `DSCORD_MEMORY_ENDPOINT`，或配套 `DSCORD_MEMORY_LLAMA_SERVER` / `DSCORD_MEMORY_GGUF`。变量与配置读取规则见 [native.mjs](native.mjs)。

## 状态、恢复与备份

语义检索会派生索引、核对原文并返回实际模式。向量路径失败时可返回 `lexical-fallback` 及原因，不算语义检索成功。索引可补建，来源正文、修订和撤回不随重建改写。该后端仍有固定索引容量，部署前应按所用后端容量管理数据。

自管 Ombre 或 Harrier 退出后，后续操作尝试恢复原库和服务；恢复失败会报告错误或明确文本回退。外部 endpoint 的可用性由其运维方保障。中断的嵌入调用可能没有完整用量回执。

内核把读过的来源、记忆与联系人行留在内存里，写入时作废对应的行，`knowledge.sqlite` 仍是唯一的记录，重启后从文件重读。因此一个 knowledge 目录只由一个内核打开；内核运行时由别的程序改动这个文件，内核不会看到。留在内存里的 JSON 文本以运行配置 `memoryCacheChars` 为上限（默认 4800 万字符，约四万条普通消息），超过后整体丢弃、按需重读，结果不变，只是变慢。

备份时停止相应内核并等待后台整理收尾，保存整个 Bot home 和 knowledge 目录；启用外部正文／索引存储时同时保存匹配后端。来源撤回与 `forget` 保留逻辑历史，不是对所有备份、原始文件或外部副本的安全擦除。

## 使用边界

当前召回排除旧版本、已撤回、过期及依赖失效的记录；显式历史读取保留状态。群范围说明适用位置，不表示全员都知道或赞同，也不是额外工具授权。

有限视图和语义排序都可能漏掉相关原文。模型的草稿、转述与推断不是人类确认；重要结论应核对原始来源与真实工具证据。来源变更不会自动修改已交付文件。[视图与按需回顾](当前上下文与回顾.md)
