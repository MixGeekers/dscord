# DS-Group 前端架构与设计规范

更新于 2026-11-05。用户要求在本次附件、工具执行和 Discord 式提及升级中建立全局设计 token，加入明亮模式和多语言，并采用 TypeScript 与 TS7。前端选用 React 19.3.1、TypeScript 7.0.2 和 Vite 8.3.5。

## 选型依据

本轮在 macOS ARM64、Node 24.19.0 上实际比较了 React TSX 与 Vue SFC。React 配合官方 TS7 完成严格类型检查、错误属性检出和生产构建。Vue 配合 `vue-tsc@3.3.14` 和官方 TS7 的直接组合出现 `typescript/lib/tsc` 导出错误，采用 Vue 维护者的 `typescript-native-bridge` 路径后同样通过。React 的应用组件及共享接口类型可以直接交给官方 TS7，本项目采用这条编译链。

TS7 已于 2026-07-08 正式发布，本项目固定 `typescript@7.0.2` 并使用 `tsc`。Vue 的桥接支持也已有官方合并记录。这里的选择依据是本项目工具链与组件维护需求，最小工程的结果仅覆盖本轮版本组合。[TS7 官方发布说明](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) · [React TypeScript 文档](https://react.dev/learn/typescript) · [Vue 原生编译器桥接](https://github.com/vuejs/language-tools/pull/6129)

## 代码职责

| 位置 | 职责 |
|---|---|
| `web/src/App.tsx` | 登录、当前会话、消息与任务等应用状态及业务操作 |
| `web/src/types.ts`、`api.ts` | 成员、房间、附件、提及、任务与接口契约 |
| `web/src/components/` | 导航、消息、编辑器、附件、任务、收件箱与设置组件 |
| `web/src/locale.ts`、`locales/` | 应用界面双语文案与 React 语言更新 |
| `web/mention-editor.js`、`attachments.js`、`pwa.js` | 已验证的光标编辑、上传传输与浏览器 PWA 模块，通过相邻类型声明接入组件 |
| `web/tokens.css` | 全局设计值与主题映射 |
| `dsh-connect/client/tokens.ts` | DSH 面板的 token，由 `scripts/panel-tokens.mjs` 从 `web/tokens.css` 生成并提交 |
| `dsh-connect/client/styles.ts` | DSH 面板的样式，只消费 `tokens.ts` 里的 token |
| `web/styles.css` | 消费语义 token 的组件布局与状态样式 |
| `web/theme.js` | 样式加载前应用主题偏好，处理系统与跨标签变化 |

新组件与应用状态使用 TS/TSX。编译启用 `strict`、`isolatedModules`、`verbatimModuleSyntax`。交互组件使用稳定身份，切换主题、语言或房间时保留编辑器内容、提及身份和所属会话的上传任务。

## 全局设计 token

| 类别 | 示例 | 使用约定 |
|---|---|---|
| 页面与控件表面 | `--color-bg-canvas`、`--color-bg-primary`、`--color-bg-input` | 按表面职责选取 |
| 正文与次要信息 | `--color-text-primary`、`--color-text-secondary`、`--color-text-muted` | 按信息层级选取 |
| 交互与状态 | `--color-accent`、`--color-focus`、`--color-status-danger` | 包含 hover、focus、disabled 与错误状态 |
| 提及 | `--color-mention-bg`、`--color-mention-text`、`--color-mention-message-bg` | 补全、消息内提及和被提及消息共用 |
| 排版 | `--font-family-ui`、`--font-size-body`、`--line-height-body` | 支持中文与拉丁文字及字体回退 |
| 间距与圆角 | `--space-*`、`--radius-*` | 从全局尺度选择 |
| 布局与层级 | `--width-channel-sidebar`、`--z-suggestions`、`--z-panel` | 按布局与浮层角色使用现有 token |
| 阴影与动画 | `--shadow-dialog`、`--motion-panel` | 跟随主题及减少动态效果偏好 |

组件样式通过变量使用颜色。身份组颜色属于用户保存的业务数据，按实际值展示。新增视觉状态先补语义 token，再由组件引用。

## 图标与活动状态

界面使用 Lucide 1.68.0。React 控件从 `lucide-react` 静态具名导入，原生 DOM 附件卡使用 `lucide` 的具名节点与 `createElement`。默认 20px、`currentColor` 和 2px 笔画，控件按 16px/24px 变体统一缩放。文件类型通过对应文件图标和元信息表达，按钮的可访问名称由控件提供，装饰性 SVG 设置 `aria-hidden`。

默认对话区以消息和消息附件为主。任务执行状态仅在输入栏旁以轻量三点呈现，结束后消失，并响应减少动态效果偏好。工作记录通过显式入口打开模态层，取消与历史状态在该层操作。图标使用 Lucide（ISC 许可证）。

## 主题与语言

主题提供深色、明亮、跟随系统三种偏好，保存于 `ds-group.theme`。页面以 `html[data-theme]` 选择对应 token 值，主题脚本在首屏样式前执行。系统模式响应 `prefers-color-scheme`，同时处理其他标签页对偏好的修改。

2026-11-05 按用户要求将账号头像固定在最左侧服务器栏底部，点击打开账号菜单。菜单显示账号身份，提供个人设置、切换账号、语言、明暗模式和主题颜色。服务器列表可独立滚动，键盘 Escape 与点击外部可关闭菜单。手机侧栏展开后使用相同入口。

主题颜色提供靛蓝、蓝色、青绿、玫瑰和琥珀，保存于 `ds-group.theme-color`，通过 `html[data-accent]` 映射全局强调色、悬停和提及状态。账号菜单和个人设置复用 `AppearanceControls`，偏好即时更新并同步到同源标签页。

语言提供简体中文、English 和跟随系统，保存于 `ds-group.language`。界面文案使用翻译键与命名占位符，日期、时间、数字和文件尺寸使用 Intl。切换语言更新 `html.lang`、按钮、菜单、占位符和无障碍标签。成员名称、房间名称和聊天内容按服务器数据展示。

左栏首页、浏览器 favicon、PWA 与 Apple Touch Icon 使用用户选定的鲸鱼与人类气泡 Logo。用户随后要求顶部 Logo 采用灰度、透明背景，首页入口通过透明标志的 CSS mask 使用主题中的中性色，明暗模式分别提供对应对比度。`web/icons/` 中六份部署资源直接复制自品牌资产提交 `450cc31c015decf28b304a3287c04b0ea21c7c97`，已核对 SHA-256 一致。PWA 构建按实际资源重新生成离线缓存版本。安装后的系统图标更新仍待手机实机验证。

## 共享 UI 基础层（2026-11-05）

用户批准采用 shadcn/ui + Base UI，并授权两入口表单迁移。`ui/` 保存可修改的 shadcn 风格 Button、Input、Textarea、NativeSelect、Checkbox、RadioGroup/Radio、Popover 与 Dialog 封装；Base UI 为按钮、输入、勾选/单选和浮层提供底层交互。原生 select、文件及颜色输入通过共享封装保留浏览器表单能力。聊天端和后台分别通过 Vite 8 与 TS7 编译同一源码。Tailwind 4.3.4 仅引入 theme/utilities，原有 CSS reset 仍由两入口控制。共享样式消费本文的语义颜色、间距、焦点和浮层 z token，Portal 从 `html` 继承明暗、强调色及 `lang`。

首批迁移覆盖账号菜单、个人设置和后台准入；第二批覆盖聊天端登录注册、建群、Bot、身份组、通知、收件箱、消息表单，以及独立后台其余管理表单。Base UI 的隐藏 input 参与 FormData，共享封装在有效的原生 reset 后同步可见状态，并尊重被取消的 reset；fieldset 禁用状态显式传入交互原语。PWA 通知控件的 DOM 绑定在 Dialog Portal 就绪后初始化，成功刷新清除前次网络错误；账号切换、草稿、提及和附件仍由业务组件持有。

图标继续统一使用已授权的 Lucide 1.68.0，保留鲸鱼与气泡品牌 Logo；新控件的内嵌图标遵循 16/20px 尺寸、`currentColor`、2px 笔画和 8px 左右间距，禁用与主题颜色由控件 token 驱动。此决定与 [shadcn/ui 官方手动安装文档](https://ui.shadcn.com/docs/installation/manual)中 `lucide-react` 的默认示例一致；不额外引入另一图标依赖。

最左全局栏的 Bot 入口独立于服务器列表。Bot 区二级侧栏展示当前所有者的完整 Bot ID 与管理、新建操作；自己 Bot 的私聊在归属服务上打开，并按房间 ID 恢复草稿、未读和最近会话。服务器图标只高亮服务器频道视图，群成员栏继续按实际房间成员关系展示 Bot。设置及原生模态层采用固定外框、独立滚动内容和固定标题/操作区，窄屏外框受 `100dvh` 约束。

## DSH 面板（2026-11-10）

用户要求统一网页与 DSH 插件的设计，并让第一次用的人马上能用。网页、两个后台和 DSH 面板现在共用一套 token 名称与尺度，来源只有 `web/tokens.css`。

### token

`npm run build:dsh-client` 先由 `scripts/panel-tokens.mjs` 生成 `dsh-connect/client/tokens.ts`，再打包面板。字号、字重、行高、间距、圆角、焦点宽度和动画时长原样取自 `web/tokens.css`；颜色、字体和两档圆角跟随 DSH 自己的主题，写成 `var(--dsw-…, 我们的值)`，面板在 DSH 明暗主题下与宿主一致，离开宿主时回落到 DSCord 的值。

| 我们的 token | DSH 的 token |
|---|---|
| `--color-bg-primary`、`--color-bg-input` | `--dsw-alias-bg-layer-1` |
| `--color-bg-secondary` | `--dsw-alias-settings-card-fill` |
| `--color-bg-hover` | `--dsw-alias-interactive-bg-hover` |
| `--color-text-primary` | `--dsw-alias-label-primary` |
| `--color-text-muted` | `--dsw-alias-label-secondary` |
| `--color-border-subtle`、`--color-border-normal` | `--dsw-alias-settings-card-stroke` |
| `--color-accent`、`--color-focus` | `--dsw-alias-state-business-primary` |
| `--color-link` | `--dsw-alias-link` |
| `--color-status-success`、`--color-status-warning` | `--dsw-alias-state-success-primary`、`--dsw-alias-state-warn-primary` |
| `--color-status-danger`、`--color-text-danger` | `--dsw-alias-state-error-primary` |
| `--radius-lg`、`--radius-xl` | `--dsw-radius-md`、`--dsw-radius-lg` |
| `--font-family-ui` | `--dsw-font-family` |

token 只定义在 `.dscord-connect` 上，不影响 DSH 的其他页面。面板要用新的 token 时，在 `scripts/panel-tokens.mjs` 的对照表或共享名单里加一项。`tests/dsh-client-build.test.mjs` 检查三件事：`tokens.ts` 是当前 `web/tokens.css` 的生成结果；面板样式里没有写死的颜色，也不直接引用 `--dsw-*`；字号、间距和圆角都来自 token。按钮和单行输入框继续用 DSH 的 `Button`、`Input`，原生 select、textarea、单选和复选由面板样式按同一套 token 绘制。

### 从零到 Bot 上线

Bot 的配置在网页上做，保存在中央；DSH 面板只负责连接和显示状态（2026-11-10，用户提出：「配置应该在 DSCord 上做，DSH 只管连接，其他全通过中央服务器配置」）。

| 步骤 | 位置 | 操作 |
|---|---|---|
| 1 | 网页「添加 Bot」 | 填名字（职责、模型可选），点「创建 Bot」。中央建 Bot 账号并保存设置，Bot 默认加入当前服务器 |
| 2 | 同一个对话框 | 还没有设备时给出连接密钥，点「复制连接密钥」 |
| 3 | DSH 的 DSCord 面板 | 粘贴，识别到完整密钥后自动连接；设备按中央的设置创建 Bot 并上线，对话框显示「在线」和「去聊天」 |

已经连接过设备的人只有第 1 步：创建后设备几秒内让 Bot 上线。面板顶部的三步引导（连接账号、添加 Bot、上线）标出当前该做的一步，有 Bot 上线后不再显示。

### 网页上的 Bot 设置

- 「添加 Bot」（`CreateBotDialog`）：名字必填；「运行设备」始终显示，列出连接过的设备和在线情况，默认选在线的那台，还没有设备时说明创建后会给连接密钥、第一台连上的设备运行它；模型选项来自所选设备报告的模型目录，默认「跟随设备默认」，设备上缺密钥的模型照常列出并注明。创建后同一个对话框按 Bot 的状态往下走：还没有设备、设备离线、正在上线、在线。
- 「我的 Bot」（`MyBotsDialog`）：每个 Bot 一行，显示它在当前服务器上的状态；「设置」里改名字、职责、模型、运行设备，并让它加入或退出当前服务器。下面的「设备」列出连接过的 DSH（在线情况、默认模型、插件版本），可以移除，也可以再连接一台。
- 两处共用 `BotSetup.tsx` 的字段和状态标签，数据来自 `managed-bots.ts`：对话框打开时每 3 秒读一次中央的 Bot 和设备。状态按人处理问题的顺序给出：先看设备，再看设置，最后看连接。
- 没有中央会话的登录（例如旧会话）只能查看，页面说明需要用中央账号登录。

### 面板结构

- 页眉：账号和这台设备的名字、退出登录、刷新。操作结果和错误固定在页面顶部，滚动时保持可见。
- 这台设备运行的 Bot：每个 Bot 一张只读卡片，列出它用的模型、在每台聊天服务器上的状态和「去聊天」；没有 Bot 时指向网页。
- 插件版本：当前版本、兼容情况和检查更新；升级方式收起，摘要里显示当前选择。
- 更多设置：参与判断服务和本机配置目录。

插件升级和参与判断服务目前仍在面板里，下一步搬到网页和中央后，面板只剩连接。

### 验证范围

2026-11-10 本地通过 `npm run check`、`npm run build` 和全部浏览器测试文件。`tests/react-bots.browser.mjs` 用真实 Chromium、真实中央服务器和真实控制器走完整条链路：网页创建 Bot、复制密钥、设备连接、Bot 上线、在网页改名字职责模型、退出和加入服务器、移除设备；聊天服务器和 DSH 内核是合成的。面板测试的宿主也是合成的：DSH 的 `Button`、`Input` 是无样式替身，`--dsw-*` 没有定义，颜色走回落值。没有在真实 DSH 里装包核对，宿主内的实际观感仍待核对。
